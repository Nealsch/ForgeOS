# ADR-006: Relocate Repository Automation Scripts to the ForgeOS Project

**Status:** Accepted

## Context

Early versions of ForgeOS included a top-level `Scripts` directory intended to hold utility scripts used during development.

As the architecture has evolved, ForgeOS now has a clear separation between:

* **Framework** – reusable software engineering knowledge.
* **Tooling** – reusable integrations with AI platforms and external systems.
* **ForgeOS Project** – the implementation and evolution of the ForgeOS framework itself.

The existence of a top-level `Scripts` directory implies that scripting is a first-class architectural component alongside the Framework and Tooling. This no longer reflects the intended architecture.

Repository automation is an implementation concern of the ForgeOS project, not part of the reusable framework.

## Decision

The top-level `Scripts` directory will be removed.

Repository automation scripts will instead be located under:

```text
ForgeOS Project/
└── Scripts/
```

The `Scripts` folder will contain automation that supports the development and maintenance of the ForgeOS repository itself.

Typical examples include:

* Repository validation
* Documentation generation
* Index generation
* Template scaffolding
* Release preparation
* Migration utilities
* Repository maintenance tasks

## Consequences

### Positive

* Reinforces the separation between reusable framework knowledge and project implementation.
* Simplifies the top-level repository structure.
* Makes it clear that scripts are implementation details rather than architectural components.
* Keeps Framework and Tooling focused on their intended responsibilities.
* Provides an appropriate home for repository maintenance and automation.

### Negative

* Existing documentation referencing the top-level `Scripts` directory must be updated.
* Existing scripts must be relocated to the new location.

## Architectural Principles

Repository automation is **not** part of the ForgeOS Framework.

Scripts must not contain:

* Engineering standards
* Skills
* Templates
* Examples
* Collaboration orchestration
* Platform integrations
* Project technology implementations

Those responsibilities belong within the Framework, Tooling or individual projects.

The ForgeOS Framework must remain fully functional without the presence of the `Scripts` directory.

Scripts exist solely to automate repository maintenance and improve the developer experience. Their removal should not alter the behaviour, architecture or engineering guidance provided by ForgeOS.

## Updated Repository Structure

```text
ForgeOS/

├── Framework/
├── ForgeOS Project/
│   ├── ADR/
│   ├── Backlog/
│   ├── Roadmap/
│   ├── Release Notes/
│   └── Scripts/
├── Tooling/
├── README.md
├── AGENTS.md
├── LICENSE
├── .clinerules
└── .gitignore
```

## Rationale

ForgeOS distinguishes between three separate concerns:

* **Framework** defines reusable engineering knowledge.
* **Tooling** provides reusable integrations with AI platforms and external systems.
* **ForgeOS Project** manages the implementation and evolution of ForgeOS itself.

Repository automation supports the development of the ForgeOS project and therefore belongs within the ForgeOS Project rather than as a top-level architectural component.
