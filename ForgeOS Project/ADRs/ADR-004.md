## Decision Title

**ADR-004: Define ForgeOS Agents as Specialist Engineering Roles**

---

## Context

ForgeOS is founded on the principle that every framework component has a single, well-defined responsibility.

As the framework evolved, the introduction of Collaboration Orchestration and the AI Program Manager clarified the distinction between project coordination and engineering execution.

Without explicit architectural boundaries, there is a risk that ForgeOS Agents become responsible for both coordinating engineering work and performing specialist engineering activities.

This would create overlapping responsibilities, reduce reusability and weaken the separation of concerns that underpins the ForgeOS architecture.

ForgeOS therefore requires a clear definition of what constitutes an Agent and the responsibilities that belong to that role.

---

## Decision

ForgeOS Agents shall represent **specialist engineering roles only**.

Each Agent is responsible for a specific engineering discipline within the Software Development Lifecycle and performs work using one or more ForgeOS Skills.

Examples include:

* Product Manager
* Architect
* Backend Engineer
* Frontend Engineer
* Codebase Analyst
* QA Engineer
* Security Engineer
* DevOps Engineer
* Technical Writer

> **Editorial note (2026-09-07, WI-001):** The example list was amended in place to match the agent catalogue actually defined in `Framework/04-Agents/` (per ADR-006 naming conventions). The decision itself is unchanged.

Agents are invoked as required by the Collaboration Orchestration layer and coordinated by the AI Program Manager.

Agents are **not** persistent conversational entities and do **not** manage the overall software project.

---

## Responsibilities

A ForgeOS Agent is responsible for:

* Performing activities within its engineering discipline.
* Applying the appropriate ForgeOS Skills.
* Following applicable ForgeOS Standards.
* Producing engineering artefacts.
* Participating in reviews within its area of expertise.
* Providing specialist recommendations and decisions.

Agents are intentionally focused on engineering execution rather than project coordination.

---

## Responsibilities Explicitly Excluded

ForgeOS Agents do **not**:

* Manage the overall software project.
* Maintain long-term project context.
* Coordinate other Agents.
* Determine the overall Software Development Lifecycle progression.
* Decide which engineering disciplines should be engaged.
* Select the project's execution strategy.
* Act as the primary interface with the Product Owner.

These responsibilities belong to the AI Program Manager and the Collaboration Orchestration layer.

---

## Alternatives Considered

### Allow Agents to coordinate engineering work

**Rejected**

This creates overlapping responsibilities between Agents, Collaboration Orchestration and the AI Program Manager, reducing architectural clarity.

---

### Make Agents persistent AI personas

**Rejected**

Persistent collaboration is the responsibility of the AI Program Manager.

Agents should remain reusable engineering specialists that can be invoked whenever their expertise is required.

---

### Define Agents as specialist engineering roles

**Selected**

This preserves clear separation of concerns and supports a scalable engineering model.

---

## Rationale

Restricting Agents to specialist engineering responsibilities reinforces the core architectural principles of ForgeOS.

The AI Program Manager manages the project.

Collaboration Orchestration determines how work should be executed.

Agents perform the engineering work.

Skills provide the reusable capabilities used by those Agents.

This layered architecture ensures that every component has a single responsibility and can evolve independently.

It also enables future implementations where specialist Agents may become independently executable AI systems without requiring changes to the ForgeOS architecture.

---

## Consequences

### Positive

* Clear separation of responsibilities.
* Highly reusable Agent definitions.
* Improved maintainability.
* Simplified onboarding.
* Strong alignment with the Single Responsibility Principle.
* Enables Collaboration Orchestration to coordinate engineering activities consistently.
* Supports future multi-agent execution models without changing the framework architecture.

### Trade-offs

* Requires clear documentation describing the relationship between the AI Program Manager, Collaboration Orchestration and ForgeOS Agents.
* Contributors must understand the distinction between project coordination and specialist engineering execution.

## Completion Criteria

* ForgeOS Agent documentation defines Agents as specialist engineering roles.
* Agent responsibilities exclude project coordination.
* Collaboration Orchestration is responsible for determining which Agents are required.
* The AI Program Manager is defined as the persistent collaborative interface with the Product Owner.
* Skills remain reusable capabilities consumed by Agents.
* Future ForgeOS Agents can be introduced without changing the overall collaboration model.
