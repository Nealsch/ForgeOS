# ADR-007: Codebase Analysis is an Agent, Not a Skill

**Status:** Accepted

## Context

As ForgeOS has evolved, a distinction has emerged between **engineering outcomes** and **reusable engineering capabilities**.

Initially, Codebase Analysis was considered as a ForgeOS Skill responsible for analysing a software repository using tools such as Graphify.

Further architectural review identified that Codebase Analysis performs responsibilities beyond those appropriate for a Skill. It is responsible for determining what analysis is required, selecting appropriate tooling, orchestrating multiple engineering activities, interpreting results and producing engineering recommendations.

These responsibilities align with the role of an engineering Agent rather than a reusable Skill.

## Decision

Codebase Analysis will be implemented as a ForgeOS Agent.

The Codebase Analysis Agent is responsible for developing and maintaining an understanding of a software system's architecture and implementation.

The Agent may invoke one or more Skills and Tooling capabilities to achieve this outcome.

Graphify is recognised as a preferred implementation of a codebase analysis capability, but ForgeOS will remain independent of any specific analysis tool.

## Responsibilities

The Codebase Analysis Agent is responsible for:

- Assessing repository architecture.
- Determining whether architectural analysis is required.
- Selecting appropriate analysis techniques.
- Invoking codebase analysis tooling.
- Interpreting analysis results.
- Producing architectural summaries.
- Identifying technical debt.
- Identifying architectural risks.
- Supporting migration assessments.
- Providing architectural context to other Agents.

The Agent does **not** perform low-level engineering tasks directly. Instead, it orchestrates Skills and Tooling capabilities.

## Relationships

The architectural relationship becomes:

↓

## Agent Responsibilities

The Codebase Analysis Agent owns the engineering outcome of architectural understanding.

Typical activities include:

- Repository assessment
- Architecture review
- Technical debt analysis
- Dependency analysis
- Migration assessment
- Documentation generation
- Architectural reporting

The Agent determines which Skills and Tooling capabilities are appropriate for each situation.

## Skills

The Agent may invoke Skills including:

- Architecture Analysis
- Dependency Analysis
- Technical Debt Assessment
- Documentation Generation
- Migration Assessment
- Repository Metrics
- Security Surface Review

Skills remain reusable engineering capabilities and do not coordinate overall analysis.

## Tooling

Graphify becomes a Tooling capability rather than a ForgeOS Skill.

The Tooling layer is responsible for interacting with external analysis tools and producing architectural artefacts.

ForgeOS intentionally abstracts these implementation details from the Framework.

Future implementations may replace or supplement Graphify without requiring changes to the Agent or Skill architecture.

## Consequences

### Positive

- Clarifies the distinction between Agents and Skills.
- Reinforces the responsibility of Agents to own engineering outcomes.
- Maintains ForgeOS independence from specific tooling.
- Allows multiple analysis tools to be supported through a common interface.
- Supports future expansion of architectural analysis capabilities.

### Negative

- Existing plans describing Codebase Analysis as a Skill must be updated.
- Additional Skills may be required to support the Agent.

## Architectural Principle

ForgeOS distinguishes between engineering outcomes and engineering capabilities.

- **Agents** own engineering outcomes and orchestrate work.
- **Skills** provide reusable engineering capabilities.
- **Tooling** integrates ForgeOS with external platforms and technologies.
- **Templates** standardise engineering artefacts.
- **Examples** demonstrate best practice.

This separation ensures that engineering knowledge remains reusable, platform-independent and adaptable as new tools and techniques emerge.

## Rationale

Codebase Analysis is fundamentally an engineering discipline rather than a single reusable capability.

Treating it as an Agent enables it to coordinate multiple Skills, invoke appropriate Tooling, interpret results and provide architectural guidance without coupling ForgeOS to a specific implementation such as Graphify.

This decision further reinforces the layered architecture of ForgeOS and aligns with the principle that Agents are responsible for engineering outcomes while Skills provide reusable capabilities.
