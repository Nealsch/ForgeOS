# Implementation Documentation

## Purpose

Document the implementation details, design decisions, and operational considerations for a software component.

## When Used

Use this template when implementation work is completed, reviewed, or handed off to another team.

## Produced By

Forge-Backend-Development, Forge-Frontend-Development, Forge-Database-Implementation, or equivalent implementation activity.

## Consumed By

* Engineers
* QA
* Operations
* Reviewers

## Template

### Component Overview

Describe the component, its responsibilities, and its place in the system.

### Implementation Details

Document the key implementation choices, structure, and behaviour.

### Interfaces

List the public interfaces, APIs, or integration points provided by the component.

### Dependencies

Capture dependencies on libraries, services, systems, or other components.

### Configuration

Document configuration options, defaults, and required environment settings.

### Operational Considerations

Note performance, scaling, monitoring, and deployment considerations.

### Known Limitations

Document any current limitations or known issues.

### Related Design and Decisions

Link to related architecture, data, or decision records.

## Completion Criteria

* The component purpose and design are documented.
* Interfaces and dependencies are clear.
* Operational considerations and limitations are captured.
* Related design artifacts are referenced.
