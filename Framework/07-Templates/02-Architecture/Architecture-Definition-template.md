# Architecture Definition

## Purpose

Define the high-level system architecture, context, boundaries, and key structural decisions.

## When Used

Use this template once requirements are understood and the solution approach needs to be documented for design and implementation.

## Produced By

Forge-Solution-Architecture or equivalent architecture definition activity.

## Consumed By

* Architects
* Engineers
* QA
* Stakeholders

## Template

### Architecture Overview

Describe the system purpose, scope, and target users.

### System Context

Summarise the system boundaries, external dependencies, and interactions with other systems.

### Components

List the primary components or services and their responsibilities.

### Data Flow

Outline the key data flows and integration points.

### Integration Overview

Describe how major subsystems and external systems communicate.

### Key Decisions

Record important architecture decisions, rationale, and alternatives considered.

### Risks and Constraints

Capture architectural risks, constraints, and assumptions.

## Completion Criteria

* The architecture is communicated clearly and concisely.
* System boundaries and responsibilities are defined.
* Data and integration flows are understood.
* Key decisions and risks are documented.
* The document is usable by implementation and review teams.
