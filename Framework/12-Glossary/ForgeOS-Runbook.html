ForgeOS Operations Runbook

Version: 1.0
Status: Active
Last Updated: 2026-07-19

Purpose

The Operations Runbook provides the day-to-day operational procedures for managing the Forge Sitesmiths production infrastructure.

Unlike the architecture and standards documentation, this document focuses on how to perform common operational tasks.

It should contain repeatable procedures that can be followed without relying on memory.

📂 Terminal Navigation & File Operations

pwd                 # Print working directory
ls -a               # List all files, including hidden ones
cd <path>           # Change directory
cd ..               # Move up one directory
mkdir <name>        # Create a directory
touch <file>        # Create an empty file
rm -r <dir>         # Remove a directory recursively
clear               # Clear the terminal
:wq                 # Save and quit Vim

⚙️ Git Configuration

git config --global user.name "Name"                 # Set your commit username.
git config --global user.email "email"                 # Set your commit email.
git config --global color.ui auto                 # Enable colored terminal output

📝 Tracking & Committing Changes


git status                 # Show tracked, untracked, and staged files.
git diff                 # View unstaged changes in your files.
git add <file>                 # Stage a specific file for commit.
git add .                 # Stage all file changes in directory.
git commit -m "msg"                 # Commit staged changes with message.
git commit -am "msg"                 # Stage and commit tracked files directly.
git commit --amend                 # Modify the most recent commit

Standard Deployment Workflow

Local Machine

git add .

git commit -m "Description"

git push origin main

VPS

cd /opt/repos/forge-sitesmiths

git fetch origin

git status

git rev-parse HEAD

git rev-parse origin/main

git branch -vv

git log --oneline --graph --decorate --all --max-count=15

git pull

docker compose up -d

Verify

git status

docker ps
Your branch is up to date with 'origin/main'.

Emergency Rollback

docker compose down

git checkout <commit>

docker compose up -d

Restore backups if required and validate the deployment.

Operational Philosophy

The runbook should always reflect the current production environment.

  1. Update the infrastructure.
  2. Test the procedure.
  3. Update this Runbook.
  4. Commit the documentation.

A runbook that is not maintained cannot be relied upon during an incident.
